# Практическая работа 7 Рефакторинг по БЭМ

Работа продолжает многостраничный учебный магазин из практики №6.
Классы и CSS-селекторы приведены к единой системе, сохранены страницы,
Flexbox-навигация, Grid-раскладка и обработка формы в JavaScript.

## Аудит исходного проекта

| До рефакторинга | Проблема | После рефакторинга |
| --- | --- | --- |
| `header`, внутренний `.site-header`, `.site-logo` | Шапка оформлялась тегом, класс блока относился к внутреннему контейнеру | `.site-header`, `.site-header__inner`, `.site-header__logo` |
| `.site-nav__list li`, `.site-nav__list a` | Оформление зависело от вложенных тегов | `.site-nav__item`, `.site-nav__link` |
| `.site-nav__list a[aria-current="page"]` | Вариант ссылки не был выражен модификатором | `.site-nav__link--active`, ARIA-атрибут сохранён |
| `.product-card h3`, `.product-card p`, `.product-card .button` | Части карточки не имели самостоятельных селекторов | `.product-card__title`, `.product-card__description`, `.product-card__price`, `.product-card__button` |
| `.product-card__link` в каталоге | Одно назначение получало разные имена и не имело собственного CSS | Общий `.product-card__button` для действия карточки |
| `.breadcrumbs a`, `.breadcrumbs span::before` | Стили зависели от тегов | `.breadcrumbs__link`, `.breadcrumbs__current::before` |
| `.form-field`, `.form-actions`, вложенные `input`, `select`, `textarea` | Общие имена и привязка к структуре формы | `.order-form__field`, `.order-form__actions`, `.order-form__input`, `.order-form__select`, `.order-form__textarea` |
| `[aria-invalid="true"]` | Общий селектор мог затрагивать другие компоненты | Модификаторы полей `--error`, синхронизированные с `aria-invalid` |
| Заголовок модального окна без класса | Отсутствовал именованный элемент | `.order-dialog__title` |
| `.filters-form`, `.filters-note`, вложенные теги | Части фильтров не были связаны с блоком | `.catalog-filters__form`, `.catalog-filters__note`, `.catalog-filters__group` и остальные элементы |
| `.hero-link`, `.contact-details li` | Части блоков назывались неодинаково | `.hero__link`, `.contact-details__item` |
| `footer` и внутренний `.site-footer` | Оформление внешней области зависело от тега | `.site-footer`, `.site-footer__inner` |
| Два набора правил окна, полей формы и ошибок | Дубли усложняли каскад | Единые группы правил, переменные в начале CSS |

Классов `red`, `big`, `left`, `block1` и подобных в исходном проекте не было.
Селекторы по `id` и inline-стили отсутствовали и не добавлялись.

Основной дизайн сохранён. Для демонстрации модификаторов первый товар получил
`product-card--featured`, а кнопки формы — общий блок `button` с вариантами
`button--primary` и `button--secondary`. Цены и содержание товаров не изменены.

## Проверка результата

Проверка выполнена в Chrome через Playwright на локальном HTTP-сервере.
На трёх страницах проверены БЭМ-классы, наличие базовых классов у модификаторов,
активный пункт меню, структура шапки и подвала, хлебные крошки, карточки и раскладка.
Проверены все локальные ссылки, ресурсы и цели якорей.

На главной проверены три кнопки заказа и общая кнопка обращения, скрытое поле
выбранного товара, закрытие кнопкой и Escape, начальный фокус и его возврат.
Проверены пустая форма, неверные e-mail и телефон, корректное заполнение,
сброс ошибок при повторном открытии, успешное сообщение и очистка формы.
Ошибки синхронизированы с модификаторами и сохраняют красную границу при фокусе.

Дополнительно проверены отсутствие изменения границ полей при наведении,
затемнение остальных полей при выборе одного, возврат светлого фона,
наведение на меню, клавиатурный фокус, сетка в 3, 2 и 1 колонку при ширинах
1440, 800 и 540 px, а также `prefers-reduced-motion`.
Ошибок выполнения JavaScript не обнаружено. Снимки трёх страниц и формы
просмотрены визуально: наложений и пропавших элементов нет.

## Ответы на вопросы для самопроверки

1. **Что означает БЭМ?** Блок, элемент, модификатор — три понятия для организации интерфейса и имён CSS-классов.
2. **Что такое блок?** Самостоятельный компонент, например `product-card` или `order-form`.
3. **Что такое элемент?** Часть конкретного блока, например `product-card__price`.
4. **Что такое модификатор?** Вариант или состояние блока либо элемента, например `button--secondary` или `order-form__input--error`.
5. **Как записывается элемент?** Через двойное подчёркивание: `block__element`.
6. **Как записывается модификатор?** Через двойной дефис: `block--modifier` или `block__element--modifier`. Базовый класс сохраняется.
7. **Почему блок должен быть самостоятельным?** Чтобы его можно было перенести на другую страницу без зависимости от внешнего контейнера.
8. **Почему элемент не должен существовать отдельно от блока?** Его назначение определено блоком: `product-card__price` означает именно цену карточки.
9. **Почему `red`, `big`, `left` — плохие имена?** Они описывают оформление, которое может измениться, и не объясняют назначение компонента.
10. **Почему лучше избегать стилизации через `id`?** Селектор имеет высокую специфичность, а уникальный идентификатор неудобен для повторяемых компонентов. В проекте `id` служат якорям, JavaScript и связям доступности.
11. **Почему inline-стили усложняют поддержку?** Значения дублируются в разметке, обходят общий CSS и требуют правок на каждом экземпляре.
12. **Как БЭМ уменьшает вложенность?** Прямой класс `.product-card__title` заменяет цепочку контейнеров и тегов, поэтому правило меньше зависит от структуры HTML.
13. **Почему карточку удобно оформить блоком?** Одно оформление и структура используются и на главной, и в каталоге.
14. **Почему кнопка может быть блоком?** Её оформление применяется в разных компонентах. В карточке смешиваются `button` и `product-card__button`.
15. **Почему форма и окно — отдельные блоки?** Окно управляет модальным представлением, форма — полями и действиями. Форму можно разместить вне окна.
16. **Что проверить в JavaScript после переименования?** Селекторы и модификаторы, все обработчики заказа, передачу товара, закрытие, фокус, валидацию, очистку и сообщение об успехе.
17. **Когда рефакторинг успешен?** Классы последовательно следуют БЭМ, каскад упрощён, оформление и поведение страниц сохранены, README обновлён, изменения оформлены отдельной веткой и Pull Request.
